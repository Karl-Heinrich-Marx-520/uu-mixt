# UU&Mixt

两位作者各自独立经营的双面技术博客。站点名称 `UU&Mixt`，域名 `uuandmixt.com`（备案网站名另为「丞翰的技术笔记」）。

- **UU** —— C++ 后端 / 网络编程 / 科研复现（**唯一的工程实施者**，本地写作）
- **Mixt** —— PWN 二进制安全（**仅内容作者**，经网页上传入口写作，不接触代码）

两位作者共享域名与视觉外壳，但内容、导航、主题色与分类体系完全隔离，通过整站翻转在两面之间切换。

> ⚠️ **Mixt 面的二进制安全内容必须遵守 PRD 3.7 的措辞规则** —— 备案主体为 UU 个人，内容合规责任在备案主体。

## 开发期访问

域名未备案，**大陆地域 ECS 未备案时 80 / 443 端口被封禁，与是否绑定域名无关**。因此开发与预览期使用：

```
http://<服务器公网IP>:8080
```

仅供两位作者内部预览，不对外宣传、不提交搜索引擎。正式上线改为 443 并挂证书即可。

## 构建与部署

**构建只在本地**（服务器 2C2G，不做构建）：

```bash
# 1) 本地构建（产物在 dist/）
npm run build

# 2) 交付自检（逐路由身份 / 空白页 / 死链 / 交付件；失败会非零退出）
node scripts/check-pages.mjs

# 3) 上传（由 master 执行，仓库内不保存任何服务器凭据）
./deploy.sh
```

> `deploy.sh` 与服务器配置属 **master 职责**，前端开发不碰。G4「部署不超过 3 条命令」即上面三步。

## 环境与踩坑

> 遇到环境问题**当天**记到这里。完整踩坑表见 [`AGENTS.md` §7](AGENTS.md)。

| # | 坑 | 绕法 |
|---|---|---|
| 1 | 仓库路径含 `&`（`UU&Mixt`），shell 中未加引号会被当作后台执行符 | 所有命令中的路径必须加引号 |
| 2 | 本机 `core.autocrlf=true`，与 Linux 服务器混用会产生整文件级假 diff | 已用 `.gitattributes` 统一为仓库内 LF |
