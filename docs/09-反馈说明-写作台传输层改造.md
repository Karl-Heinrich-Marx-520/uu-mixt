## 0. 一句话结论

写作台登录报 `Failed to fetch`——不是前端代码 bug，是浏览器直连 `api.github.com` 在国内网络不可达。根治 = **写作台与 GitHub 彻底解耦**：写入、读取、登录验证全部走服务器自己的 API（同机房毫秒级），GitHub 降级为**每天一次**的异步备份。已拍板，照此实施。

## 2. ⭐ 核心改造逻辑（先读，这是本任务包的全部意义）

**UU 拍板（2026-09-15）：写作台的「写、读、登录验证」三件事全部由服务器承担，写作台一切请求只打本站 `/api/`，与 GitHub 彻底解耦；GitHub 降级为每天一次的异步备份。**

| 维度 | 现在（GitHub API 直提） | 改造后（服务器全接管） |
|---|---|---|
| **写**（发文/改分类/改友链/传图） | 浏览器直连 `api.github.com`（跨境，时通时断） | **服务器写入 API**——同源请求，毫秒级，`Failed to fetch` 彻底消失 |
| **读**（文章列表/内容/分类/友链） | 同上，listDir/readFile 全走 GitHub | **从服务器 git 主库的工作副本出**——作者看到的永远是服务器主库的最新状态，与 GitHub 镜像是否滞后无关 |
| **登录验证** | `GET api.github.com/user` 验 token | **服务器端验证**（`POST /api/verify`，token hash 存服务端） |
| GitHub 的角色 | 写入与读取的唯一通道（断了就瘫痪） | **降级为每天一次的异步备份**——GitHub 挂一整天也完全不影响写作台与发文 |
| 桌宠（DeepSeek） | 规则引擎版 | 同一个 Go 小服务进程预留 LLM 转发路由 `/api/pet/chat`（本期只预留，前端切换属下一批） |

一句话：**作者侧的一切只经过自己的服务器**；GitHub 变成「丢一天也无所谓、断了可追赶的异地备份」。

### 实施架构

```
作者 → 写作台 → 服务器 API（写/读/验证，同机房毫秒级）→ git commit 进服务器主库
UU 本地：git pull（服务器主库）→ npm run build → ./scripts/deploy.sh
GitHub：cron 每天一次 git push --mirror（凌晨执行；失败只告警不阻塞任何环节）
```

**本期范围**：① 服务器写入 API（Go，含验证）② 写作台传输层 `server.js` ③ 服务器 git 主库 + **每日镜像 cron** ④ 登录改造。
**本期不做**（后续批次，勿顺手实现）：桌宠前端切换 LLM（服务本期只预留 `/api/pet/chat` 路由）、PRD 6.1/3.8 修订（实施完成后由 master 执行）。

当前 `.git` 损坏（refs 丢失 + pack 索引不匹配，`git log` 报 `bad object HEAD`）；远端与工作区均完好。执行：

```bash

git status --short             # 核对工作区差异（含未提交的 deploy.sh / docs/08 / docs/09 等）
```

然后把工作区现存改动**按分区分批提交**（AGENTS.md §4；`deploy.local.sh` 已被 gitignore）。注意：`.git.empty-init-20260915/` 与 `.git.broken-20260915/` 移出跟踪范围（加 `.gitignore` 或移出仓库目录），**不要删除**（事故现场留查）。

### T5-1 · 服务器写入 API（Go，本地开发 + mock 存储）

照 `docs/06` §4.2 规格，按本次拍板细化：

| 项 | 规格 |
|---|---|
| 接口 | `POST /api/verify`（**登录验证在服务器端**：token → `{login, face}`，彻底替代 `GET api.github.com/user`）、`GET /api/list`、`GET /api/read`、`POST /api/write`（文本；图片 multipart）、`DELETE /api/file`——**与 `gh.js` 全部公开方法一一对应**（`verifyToken / getSession / clearSession / isMock / listDir / readFile / writeFile / removeFile / uploadBinary` 语义不变） |
| 鉴权 | 每作者一个随机 token（≥32 字节），服务端**只存 SHA-256 hash**；face 由 token 推导，**接口不接受 face 参数**；吊销 = 服务端删一条记录 |
| 路径白名单 | 仅 `src/content/<face>/**`、`src/config/categories-<face>.json`、`src/data/friends.json`（站点级，决策 7.16）、`public/images/<face>/**`；拒绝 `..`、绝对路径、符号链接 |
| 读取语义 | `/api/list` `/api/read` 返回**服务器 git 工作副本的最新 commit 状态**——写作台看到的内容与 GitHub 镜像是否滞后完全无关 |
| 限流与配额 | 每 token 限频；Markdown ≤ 200KB、图片 ≤ 2MB |
| 版本化 | 每次写入/删除即 `git commit`（message 规范同现有：`content(mixt): …` / `content(friends): …`），作者与时间天然入审计 |
| 失败可见性 | 所有失败返回明确中文错误 + HTTP 状态码（401 凭据无效 / 403 越权 / 413 超限 / 409 sha 冲突），**不得静默**（PRD 6.1） |
| 形态 | Go 单二进制；内存 < 50MB；**只监听 `127.0.0.1:8787`**（公网入口仅 Nginx 反代）；配置（token hash 表、仓库路径）放 `/etc/uum/` |
| 自测 | 先带内存 mock 存储在本地跑通全接口（curl 即可）；交付物 = 源码 + 交叉编译好的 linux/amd64 二进制 + systemd unit 文件 + 「master 部署说明」（一页即可） |

**分工边界**：UI agent **全程本地开发，不碰服务器**（SSH 凭据仅 master 持有；服务器有 fail2ban，多次认证失败会封 IP）。服务器落地（建主库、部署二进制、systemd、Nginx 反代 `/api/`、cron）= master 按你交付的部署说明执行。

### T5-2 · 写作台传输层 `server.js`（同接口替换 gh.js）

1. 新增 `public/scripts/admin/server.js`：API_BASE 指向**本站同源** `/api/`；全部方法语义与 `gh.js` 一致；`?mock=1` 假后端机制**保留**。
2. `desk.js` 对传输层的引用切换为 server.js（理想：`desk.js` 一行不改，仅换适配器——当初按接口语义抽象的回报点）。
3. **登录页改造**（`/admin/`）：文案改为「写作台凭据（master 私下发放的 token）」；`gh.js` 保留文件可后置清理，但**默认走 server.js**；登录失败提示分类（网络失败/凭据无效/越权），各给中文指引。
4. sha 乐观锁语义保持（409 → 提示刷新重试），文章/分类/友链/媒体四个面板行为零改动。
5. **硬性检查**：改造后写作台全流程的网络面板里**不得出现任何对 `api.github.com` 的请求**。

### T5-3 · 服务器 git 主库 + 每日镜像（master 配合的交接件）

按 `docs/06` §4.3，频率按本次拍板修订：服务器 `/srv/uum/repo.git`（bare）+ 工作副本（写入 API 的 commit 目标），**主库不得位于 Nginx 站点根下**；**cron 每天一次 `git push --mirror` 到 GitHub**（建议凌晨 4 点档，失败写告警日志——「GitHub 端点不可达」不是错误，静默等次日重试即可，反正有 24h 容忍窗口）。UI agent 交付「主库初始化与本地拉取说明」：bare 主库从 GitHub 克隆初始化 → 工作副本挂接 → UU 本地新增 server remote → 部署前拉取。**origin 切换时点**：主库建立并验证首条 commit 链路后，由 master 与 UU 确认再切，切换前 UU 照旧走 GitHub。
