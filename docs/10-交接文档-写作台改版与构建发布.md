## 2. 批次 A：写作台体验三改 + 追加（决策 7.20-7.23）

### 2.1 个人简介与个人标签编辑（7.21 / 7.23）

- **要什么**：写作台「设置」面板新增简介卡（≤200 字、实时字数、必填）与个人标签（逗号分隔 ≤6 个），同一按钮保存；展示位为**自己面的侧栏简介**与**作者页姓名下的方向行**（如「C++ 后端 · 网络编程」）。
- **正式版数据落点**：`src/config/author-uu.json` / `author-mixt.json`（`{bio, tags}`，按面拆分——token 推 face，**越面改不了他人简介**）；面页 `side-bio`、作者页 `author-bio` / `author-dir` 构建期渲染。
- **写链路**：写作台读改写 `author-<face>.json`（sha 乐观锁，409 时以仓库为准提示刷新）→ 提交形如 `config(uu): 更新个人简介与标签`。
- **改动生效时机**：简介/标签改完需构建才上前台（与文章同链路，用批次 B 的「构建发布」按钮）。

### 2.2 双面邮箱点击复制（7.22 / 7.23）

- UU 面 `2632879190@qq.com`、Mixt 面 `2118458805@qq.com`；侧栏 Follow Me 圆钮 `data-action="copy-mail"` + `data-mail`/`data-okmsg`，`core.js` 全局处理（Clipboard API，file:// 降级 execCommand，toast「QQ 邮箱已复制」）。
- 正式版邮箱在构建期由作者配置渲染；demo 同交互（demo.js `copy-mail` 分支）。

### 2.3 AI 托管摘要与标签（7.20）

- **60 字下限取消**（保留上限 120 与标签 ≤5）：作者只写标题 + 正文 + 分类；「AI 生成摘要与标签」按钮可预览，保存时空字段自动兜底；**作者已手填的内容 AI 一律不覆盖**。
- **正式版 schema 同步放宽**：`src/content.config.ts` description 下限 60 → 1——只改前端校验的话，AI 生成的短摘要会被构建期 schema 拦死；60-120 的约束改由 `/api/assist` 提示词承载。
- **端点**：`POST /api/assist {title, body} → {description, tags}`；token 推 face、限频 6 次/分/token；服务端持 `UUM_LLM_KEY` 转发 DeepSeek（**Key 绝不进前端**，PRD 铁律 5）；回复剥码栅栏取 JSON + 兜底清洗。
- 表单 description / tags 字段挂「AI 托管」徽标。

### 2.4 标签池管理面板（7.23）

- 侧边菜单新面板，全站共享、两作者均可维护：**重命名**（级联更新所有文章，新名已存在则并入并提示）、**删除**（confirm 注明影响篇数）、**新增**（先进池「待用」count=0，等文章挂靠后计数）。
- **端点**：`GET /api/tags`（全站文章标签计数 ∪ 池）+ `POST /api/tags/add|rename|remove`——服务端批量改写两面受影响文章的 `tags` frontmatter + 池文件 `src/config/tag-pool.json`，**单次 git 提交**，审计尾注 `Author-Face` 记发起者。
- `tag-pool.json` 不进写接口白名单，只能经端点改（防止绕过级联逻辑）。

## 3. 批次 B：构建发布手动触发（决策 7.24）

### 3.1 起因与拍板

Mixt 在写作台删光 Mixt 面全部文章与分类，前台零变化。排查：删除已正确落库（服务器 git log 7 删 + 4 分类提交），前台不变的真因是**前台是构建期静态产物，数据到前台要走「每日 4 点镜像 GitHub → 本地 pull → 本地构建 → deploy」的 T+1 长链**。UU 否决「等 T+1 / 缩短镜像 / 每操作即触发」后拍板：**「不需要这么复杂，先把博客工作台更新到能手动触发重新构建部署就行」**——构建上服务器（推翻 7.14「构建仍在本地」）、GitHub 降级纯灾备、本地直连 server remote。

### 3.2 变化明细

- **端点**：`POST /api/rebuild`（鉴权 → 每面限频 2 次/分 → running 防重 → 异步执行脚本；mock 2 秒假完成）+ `GET /api/rebuild`（状态快照：running/started/finished/exitCode/日志尾 2400 字节）。config.json **零改动**（rebuildScript 缺省 `/srv/uum/bin/uum-rebuild.sh`）。
- **服务器脚本 `deploy/uum-rebuild.sh`**：flock 单实例 + pending 合并并发；npm install（npmmirror，仅缺 node_modules 时）；**先删 `node_modules/.astro`**（content layer 数据存储缓存——不清它删文章后构建仍读旧索引，实测踩坑，AGENTS.md 踩坑 #23）；build → check-pages 双门禁 → rsync 替换 `/srv/uum/dist`；**失败保留旧 dist，前台永不空白**。
- **`deploy/uum-mirror.sh` 重写加固**：flock 防并发；push --mirror 前三方祖先分析——主库领先正常镜像 / GitHub 领先先快进主库 / 分叉放弃并告警，**绝不强推覆盖**。
- **写作台前端**（server.js v3 / desk.js v4 / desk.astro / admin.css）：侧边菜单「构建发布」→ confirm「重新构建并发布前台页面？约需 1-2 分钟」→ 按钮禁用进构建态 → 3 秒轮询（×100 看门狗）→ 完成「构建完成（N 秒）：前台已更新」/ 失败明示退出码 + 日志尾展开。
- **Demo 同步**（保持交互一致）：admin-desk.html 同款交互（2 秒模拟 + 伪日志），demo.css v18→v19 全站 15 页。
