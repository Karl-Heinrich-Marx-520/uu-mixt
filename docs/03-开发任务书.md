## 0. 使用规则（先读这五条）

1. **一次只发一个包。** 不要把两个包贴在同一条消息里。
2. **证据才算完成。** 每个包都要求它附截图 / 运行输出 / 实测数字；没给就退回："请补自测证据"。
3. **验收不过别自己改。** 把不合格项原文贴回给它修（例："两面隔离不合格：/uu/writing/ 第 3 条是 mixt 的文章，修复后给出全站检查证据"）。
4. **`demo/` 是交互与视觉的权威原型，全程保留**，正式站要与它逐页对照；不要让它重新设计。
5. **规格变更走正门**：demo 交互或需求变化 → 同步修订 PRD 对应章节（AGENTS.md §1）→ 必要时记入决策记录。不要在开发会话里默默改 PRD。

## 任务包 2 · 内容管线 + 内容层替换

```text

  报错必须包含文件路径 + 字段名 + 期望值

  同面去重、发布后冻结；构建期校验 slug 冲突
- 分类配置化（PRD 3.5）：每面一份配置；新增分类只改配置不改代码；
  空分类完整降级；分类改名时同步该分类下文章的分类字段
- 标签池（PRD 3.6）：全站共享、相似标签构建期警告（不阻断）
- 文章渲染：Markdown → HTML、代码块高亮 + 行号 + 一键复制、
  文章页方框拖宽与自动目录（交互按 Demo）
- 列表 / 归档生成（归档含分类与标签筛选视图）

验收标准：
1. 放一篇正确 Markdown → 自动出现在列表与归档，内容层接口语义与 Demo 一致
2. 故意写错 author / category / description → 构建失败且报错定位到文件
3. 两篇文章生成相同 slug → 构建失败并提示冲突
4. 分类改名 → 该分类下文章同步更新，无残留旧分类
5. Mixt 面分类为空 → 不渲染分类导航、不生成分类页、文章页无分类标签
6. 新增一个分类只改配置文件 → 导航与分类页自动出现

交付：feat(pipeline) 提交 + 上述 6 项自测证据（第 2、3 项必须有报错截图）。
```
