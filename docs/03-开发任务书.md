# 开发任务书 —— 驱动 UI 窗口完成正式开发

| 项目 | 内容 |
|---|---|
| 性质 | 给 **UU** 用的任务包清单：每段引用块里的文字，可直接粘贴给 UI 窗口 agent |
| 权威说明 | 本文件**不是需求权威**，需求以 `01-产品需求文档-PRD.md` 为准；本文件只定义"把 PRD 做出来"的顺序、口径与验收方式 |
| 使用规则 | 一次只发**一个**任务包；交付后按包内"验收标准"核对；通过再发下一个 |

---

## 0. 使用规则（先读这五条）

1. **一次一个包。** 不要把两个包贴在同一条消息里。
2. **证据才算完成。** 每个包都要求它附截图 / 运行输出 / 实测数字；没给就退回："请补自测证据"。
3. **验收不过别自己改。** 把不合格项原文贴回给它修（例："两面隔离不合格：/uu/writing/ 第 3 条是 mixt 的文章，修复后给出全站检查证据"）。
4. **`demo/` 保留作对照**，全程不要让它删除；视觉与交互以 demo 为基准迁移，**不要重新设计**。
5. **它要改 PRD 时先回来找我。** 需求变更（尤其是删功能、放松规格）必须经你拍板并记录到决策记录，不要在开发会话里当场答应。

> **你自己的待办**（与开发并行）：① 把 Mixt 加为仓库协作者（任务包 4 前必须完成）；② 任务包 0 结束时拍板 OAuth 中转方案；③ 准备真实文章内容（每人 ≥ 3 篇）。

```text
Demo 我已验收通过，正式开发开始。第一步不写代码，先出技术方案。

开工前先做一件事：把你工作区里所有未提交的 demo 改动按分区提交掉
（demo 相关文件用 feat(demo)/style(demo)，不要混入其他改动）。

然后基于 demo/ 现状与 docs/01-产品需求文档-PRD.md（权威需求），
产出《技术方案》，保存为 docs/04-技术方案.md，必须包含：

1. 目录结构：完整 Astro 目录树，每个目录标注所属分区（对照 AGENTS.md §2.2）
2. 两面实现方式：两面如何共享模板、如何各自承载主题变量（CSS 自定义属性方案）
3. 文章字段表：把 PRD 3.2 的 frontmatter schema 落成字段表，
   含每个字段的校验规则（PRD 3.3）——
   这是构建校验、RSS、Decap 表单三处的唯一依据
4. Decap CMS 接入方案：admin 页放哪、config 怎么写、
   OAuth 中转给出 Netlify 托管 / Cloudflare Worker / 自建 三个候选的取舍与推荐
5. 依赖清单：生产依赖 ≤ 10 个，逐个说明用途

要求：只做方案，不写代码。产出后停下等我拍板，不要自行开工。
```

> **你要做的**：审这份方案，重点看三处 —— 目录结构是否合理、字段表是否与 PRD 3.2 完全一致、OAuth 推荐是否说得清代价。拍板后回复"方案通过，开始任务包 1"。

## 任务包 1 · 工程骨架

```text
技术方案已定稿（docs/04-技术方案.md）。本次任务只做骨架，按方案实施。

目标：初始化 Astro 工程，实现两面布局 + 整站翻转 + 路由同步。

范围（本次只做这些）：
- Astro 初始化，目录结构按方案，依赖取最小集
- 两套主题变量（CSS 自定义属性）+ 两面布局
- 翻转组件：站内切换播动画 + pushState 改 URL + popstate 反向播放；
  直接访问 /uu/ 或 /mixt/ 不播动画
- 入口页本次只做占位（四状态动效是后面的任务），但要能进两面

4. 首屏 JS 实测 ≤ 30KB（给出实测数字，不要说"应该没问题"）
5. 两面隔离：/uu/ 不出现 mixt 的任何内容

视觉与交互以 demo/ 为基准迁移，不要重新设计。
交付：feat(shell) 提交 + dev server 截图 + 构建输出 + JS 体积实测。
完成后停下等我验收。
```

## 任务包 2 · 内容管线

```text
骨架已验收。本次任务：内容管线。

目标：写一篇正确的文章能自动出现在站上；写错能构建报错并定位。

范围：
- 内容目录结构（按技术方案）
- frontmatter schema 校验（PRD 3.2 字段 + 3.3 规则）：
  author 枚举、category 须已登记、title/description 长度、tags ≤ 5、
  date 合法且不晚于今天、站内死链检测
- 报错必须包含文件路径 + 字段名 + 期望值
- 分类配置化：每面一份配置，新增分类只改配置不改代码；
  空分类完整降级（PRD 3.5）
- 文章渲染 + 列表 / 归档生成（归档含分类与标签筛选视图）
- 代码块：语法高亮 + 行号 + 一键复制

验收标准：
1. 放一篇正确文章 → 自动出现在列表与归档
2. 故意写错 author / category / description → 构建失败且报错能定位到文件
3. Mixt 面分类为空 → 不渲染分类导航、不生成分类页、文章页无分类标签
4. 新增一个分类只改配置文件 → 导航与分类页自动出现

交付：feat(pipeline) 提交 + 上述 4 项的自测证据
（第 2 项必须有"故意写错"的报错截图）。
```
