# 写作台首屏提速 · 自测证据（2026-10-14）

> 对应决策 7.41、踩坑 #32。目标：作者"进入写作台要数十秒才出内容"。

## 1. 现象与定位

不是站点慢。作者一次真实会话的 nginx 时间线（`/var/log/nginx/access.log`）：

```
12:27:40  GET /admin/desk/                        ← 页面 HTML（6.3KB，与另 4 条资源同秒返回）
12:27:40  GET /api/list?path=src/content/uu
12:27:41  GET /api/read?…/boost-asio-1.md
12:27:41  GET /api/read?…/boost-asio-2.md
   …      逐篇串行，14 篇
12:27:48  GET /api/read?…/categories-uu.json
12:27:48  GET /api/read?…/author-uu.json
12:27:48  GET /api/read?…/friends.json
12:27:49  GET /api/tags
```

- **18 次请求、严格串行**（前台 `for` + `await` 逐篇读）→ 约 0.5s/次 × 18 ≈ **9-10 秒**首屏。
- 反证：同一秒内有 8 条静态资源请求落盘（并发链路正常）；服务器 load 0.07、内存 free 1.0G 无压力；
  本机直连静态资源 23ms、`/api/list` 401 路径 23ms。**慢的只有"请求数 × 往返"这一项。**

## 2. 修法

| 层 | 改动 |
|---|---|
| 服务端 | 新增 `GET /api/desk`（`uum-server/desk.go`）：一次返回 posts（含 content+sha）/categories/author/friends/tags；每篇只读一次；face 仍由 token 推导 |
| 服务端重构 | `tagpool.go` 抽出 `tagSummary()`，`/api/tags` 与 `/api/desk` 共用同一计算（口径不漂移） |
| 传输层 | `server.js` 新增 `deskBundle()`：非 mock 时请求一次，**失败返回 null**（不抛） |
| 前台 | `desk.js` 首屏走数据包；`loadPosts/loadCategories/loadBio/loadFriends/loadTags` 接受可选的包；兜底路径 `Promise.all` 并发读 |
| 顺带 | 两个写作台页面补 favicon（少一次 `/favicon.ico` 404 往返）；`server.js` 版本参数登录页/工作台统一 `?v=5` |

写路径一个字没动：保存/删除仍走 `/api/write`、`/api/file` 与各自的单文件读，乐观锁（sha 409）语义不变。

### 3.2 顺带：给 /api/ 开代理压缩（Nginx）

数据包未压缩约 188KB，而线上 `gzip_proxied` 是默认的 `off`——**客户端若经代理（请求带 `Via` 头）则不会压缩**。
已在两个 server 块补 `gzip_vary on; gzip_proxied any;`（`nginx -t` 通过后 reload），
实测带 `Via` 头的请求 `Content-Encoding: gzip` 且 `Vary: Accept-Encoding`。
线上配置已按惯例回拷 `uum-server/deploy/nginx/uum.conf`。
