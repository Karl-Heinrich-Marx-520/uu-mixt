## 1. 定位与目标

### 1.1 一句话定位

**UU&Mixt** 是一个由两位技术作者各自独立经营的、可整站翻转的对称式技术博客。两人共享域名与视觉外壳，内容、导航、主题色与分类体系完全隔离。

### 1.2 站点信息

| 项 | 值 |
|---|---|
| 站点名称 | UU&Mixt |
| 域名 | **uuandmixt.com**（已注册） |
| 备案名称 | **丞翰的技术笔记** —— 与站点展示名解耦，原因见 3.7 |
| 备案归属 | **湖南省通信管理局**（按主体证件所在省，非就读地） |
| 备案状态 | 首次备案已提交（2026-09-13），审核中 |
| 服务器 | 阿里云**轻量应用服务器** · 华东2（上海）· Ubuntu 24.04 · 2 vCPU / 2 GiB / 40 GiB 系统盘 / 不限流量 / 200 Mbps 峰值带宽 |
| 内容范围 | 技术笔记、源码阅读、项目复盘、论文复现、二进制安全与 PWN |
| 内容调性 | 偏硬、有工程细节、可复现；不写水文，不搬运热点 |
| 内容合规 | PWN / 二进制安全类内容必须遵守 3.7 的措辞规则 |
| 开发期访问 | 公网 IP + 非标准端口（如 `http://<IP>:8080`）；**备案期间不解析域名** |

### 1.3 目标用户

| 优先级 | 角色 | 核心诉求 |
|---|---|---|
| 主要 | 同行 / 同学 | 快速找到具体问题的解法，能看到可复现的细节 |
| 主要 | 面试官 / HR | 3 分钟内判断作者的技术深度与表达能力 |
| 次要 | 两位作者本人 | 检索自己过去写过的结论，充当个人知识库 |
| 非目标 | 泛技术资讯读者 | 不做热点内容，不为流量妥协 |

### 1.4 产品目标

| 编号 | 目标 | 验收标准 |
|---|---|---|
| G1 | 访客 3 秒内理解"这是两个人的博客、可以翻面" | 入口页两张作者卡片可见，不依赖解释性文字 |
| G2 | 每篇文章可独立分享，链接落到正确的一面 | 直接访问分享链接，落点正确且不播放翻转动画 |
| G3 | 两位作者发文互不干扰 | 一次发文只需改动自己面的内容文件，不触碰对方文件与共享外壳 |
| G4 | 部署一次不超过 3 条命令 | 构建 → 上传 → 生效，步骤写入 README |
| G5 | 单次搜索能找到两面的文章 | 结果中同时出现两位作者的文章，并标识归属 |
| **G6** | **两位作者都能在网页上完成发文** | 在网页上传入口完成「写作 → 提交」；Mixt 全程不需要接触代码与命令行（UU 仍保留本地写作路径） |

### 1.5 非目标

- 用户注册 / 登录体系（面向读者）
- 付费订阅、会员内容、广告位
- 移动端 App / 小程序 / 公众号同步
- 多语言 i18n
- 评论区（首期）

## 2. 协作与权限

### 2.1 协作模型：分栏自治

**产品层**：两面完全隔离。

| 层面 | 归属 |
|---|---|
| 文章内容、归档 | 各自（由 `author` 字段决定） |
| 导航结构、主题色、分类体系、作者页 | 各自 |
| 域名、视觉外壳、翻转组件、入口页、404 页 | 共享 |
| 标签池、全站搜索、RSS | 共享（单实例） |

**硬性验收点**：任一面不得出现另一面的文章。

**建设层**：角色是**不对称**的（2026-09-13 确认）。

| 角色 | 承担 |
|---|---|
| **UU** | 全部工程实现（外壳、页面、内容管线、部署）+ 自己面的内容 |
| **Mixt** | **仅自己面的内容** —— 不参与工程搭建，不接触代码与命令行 |
| AI | 文档与流程管理（master）；代码实施由独立子 agent 承担 |

Mixt 通过**网页上传入口**（见 3.8）撰写并提交文章，并通过同一入口维护自己面的分类配置。

### 2.2 权限矩阵

| 操作 | UU | Mixt |
|---|---|---|
| 撰写 / 修改 / 删除自己的文章 | ✅ | ✅（经网页入口） |
| 发布自己的文章 | ✅ | ✅（经网页入口） |
| 维护自己面的分类配置 | ✅ | ✅（经网页入口） |
| 修改对方的文章 | ❌ | ❌ |
| 修改工程文件（页面模板、组件、构建脚本、部署脚本） | ✅ | ❌ |
| 修改共享外壳（翻转 / 入口页 / 视觉框架） | ✅ | ❌ |
| 站点级设置（域名、部署、搜索配置、服务器） | ✅（技术维护者） | ❌ |
| 要求整改对方内容中的合规风险 | ✅ | — |

**合规否决权（UU 单方保留）**

备案主体为 **UU 个人**，网站内容的法律责任落在 UU 身上。因此 UU 有权要求 Mixt 修改或下架存在合规风险的内容（依据 3.7 的措辞规则）。

此项**不是内容权限，而是备案主体必须保留的责任边界**。行使时必须说明依据的具体条款，不做无理由干预。

### 2.3 技术维护者

**UU** 担任技术维护者，同时是本项目唯一的工程实施人。

| 项 | 规定 |
|---|---|
| 职责 | 全部工程实现、部署脚本、服务器与 Nginx 配置、DNS 与 HTTPS 证书、站点故障、依赖升级、站点级备份 |
| 权限边界 | **不附带内容权限** —— 无权修改对方文章内容（**2.2 的合规整改要求除外**） |
| 告知义务 | 工程改动影响 Mixt 面展示时，实施前应先告知 Mixt |
| 紧急通道 | 站点不可访问、证书过期、被攻击时可直接操作，事后同步 |

### 2.4 署名规则

| 场景 | 署名形式 | 规则 |
|---|---|---|
| 单人文章（默认） | 作者名 + 头像 | 由 `author` 决定归属面，只出现在该作者面 |
| 合写文章 | 双署名，主笔在前 | 使用 `authors: [uu, mixt]`；`author` 填主笔以决定归属面；双方定稿后由主笔提交 |
| 转载他人内容 | 文首标注来源 | **允许转载**，但必须在文首标注来源与原文链接 |

**约束**
1. 文章归属以 `author` 为准，不因参与讨论而获得署名
2. 合写文章任一方有权要求移除自己的署名，此时降级为单人文章
3. 删除署名需在提交记录中留痕，不做静默修改

### 2.5 审核约定

**不实现审核状态机，不设发布前审核。** 分栏自治下每位作者对自己的面负责。

| 类型 | 提交方式 | 说明 |
|---|---|---|
| UU 的文章 | 本地写 Markdown → 提交 | 不经他人 |
| Mixt 的文章 | 网页入口提交 | 不经他人 |
| 合写文章 | 双方定稿 → 主笔提交 | 定稿即视为双方确认 |
| 工程改动 / 共享外壳 | UU 实施 | 影响 Mixt 面展示时先告知 |
| 紧急故障修复 | UU 直接操作 | 事后同步 |

**唯一的例外是合规**：UU 可依 2.2 的合规否决权要求整改，这不受"不设审核"的约束。

> 说明：本项目的分栏自治意味着**没有"作者 → 审核 → 发布"的链条**。文章合不合规由作者自己把关，兜底的是 3.7 的措辞规则与 2.2 的合规否决权。

|---|---|---|

### 2.7 分歧裁决

| 场景 | 裁决方式 |
|---|---|
| 各自面的内容（文章、分类、主题色、作者页） | **各自决定，无需协商** |
| 共享层面（视觉外壳、入口页、标签池、搜索规则） | 提议方说明改动与影响 → 48 小时无异议即执行；有异议则协商；协商不成 **维持现状** |
| 工程实现细节（目录结构、依赖、构建方式） | **UU 决定**，实施前告知 Mixt 即可 |
| 合规风险 | 依 2.2 的合规否决权处理 |
| 紧急故障 | UU 直接执行，事后同步 |

## 3. 内容规范

### 3.1 生产与上线链路

两位作者的**写作路径不同，但汇入同一条发布链路**。

**写作路径 A · UU（本地）**

```
① 本地写 Markdown（含元数据）
② 本地构建：schema 校验 + 分类校验 + 静态生成   ← 校验失败则中断
③ 本地预览：确认排版、翻转、链接
```

**写作路径 B · Mixt（写作台）**

```
① 登录写作台（见 3.8，密码验证 → 进入本人工作台）
② 网页上写作（Markdown 正文 + 表单元数据）
③ 保存 → 提交进仓库（草稿除外）
```

**共同发布链路**

```
④ 本地构建（由 UU 执行）
⑤ 一条命令上传到服务器
⑥ 线上生效（Nginx 提供静态文件，无重启、无进程）
```

**约束**

| 约束 | 说明 |
|---|---|
| 构建一律在本地完成 | 服务器上不构建 |
| 链路上不得出现常驻服务 | 网页入口是静态管理界面，不引入本站的常驻服务 |
| **发布动作由 UU 执行** | 因构建只能本地做，Mixt 提交的文章需 UU 拉取并执行一次构建上传才会线上生效 |

**发布可见性语义（2026-09-14 随 Demo 确认）**

- **提交即发布，无审核环节**（见 2.5）：非草稿的文章在提交后即进入发布队列，页面上立即可见（Demo 已用本地内容层完整验证该语义）
- 线上生效时间仍取决于发布方式（下表 A / B，**仍待确认**）：提交到仓库后，需经一次构建与上传才会出现在线上；「无审核」与「构建耗时」是两件事

> ❓ **待确认（发布方式）**：
>
> | 方式 | 说明 |
> |---|---|
> | A. 手动发布 | 作者提交后告知 UU，UU 执行构建上传。零新增依赖 |
> | B. 自动发布 | 引入云端 CI：仓库更新后自动构建并上传，实现"提交即上线"，但新增 CI 服务与部署凭据 |
>
> 首期按 A 执行；写作台 UI 对 A / B 无感知（见 3.8 后端选型开放项）。

### 3.2 文章元数据

```yaml
---

slug:        asio-graceful-shutdown  # 必填, 系统按标题自动生成(作者不填), 发布后冻结

date:        2026-09-12              # 必填, YYYY-MM-DD
```

### 3.3 校验规则（构建期强制执行）

| 字段 | 规则 | 失败后果 |
|---|---|---|
| `author` | 必须为 `uu` 或 `mixt` | 构建失败 |
| `category` | 必须在该面分类配置中已登记 | 构建失败，提示"未登记的分类"（正常操作不会触发：删除分类时文章自动级联「未分类」，见 3.5 与决策 7.27） |
| `title` | 非空且 ≤ 60 字符 | 构建失败 |
| `description` | 60–120 字符 | 构建失败 |
| `tags` | 数量 ≤ 5，无空值 | 构建失败 |
| `date` | 合法日期且不晚于今天 | 构建失败 |
| 正文中的站内链接 | 目标必须存在 | 构建失败（死链检测） |

**报错要求**：必须包含文件路径、字段名与期望值。

### 3.4 文章状态

| 状态 | 声明方式 | 可见性 |
|---|---|---|
| 草稿 | `draft: true` | 不进构建产物；本地预览可见 |

| 下架 | 设回 `draft: true` | 线上消失，文件保留 |

状态由文件内容声明，**不存数据库**。仓库为私有，草稿可直接提交。

### 3.6 标签

| 项 | 规格 |

### 3.7 内容合规

**背景**：站点以 **UU 个人**为主体完成 ICP 备案，网站内容的法律责任落在备案主体上。Mixt 面的二进制安全内容属高风险题材，因此制定以下强制规则。

**PWN / 二进制安全类内容的措辞规则（强制）**

| # | 规则 |
|---|---|
| 1 | 不附可直接使用的 exploit payload 或 getshell 脚本；必须出现时用伪代码，或对关键偏移打码 |
| 2 | 环境一律自建（靶机 / CTF 题目），**不指向任何真实在网目标** |
| 3 | 文首统一放置合规声明：「仅用于授权环境下的安全研究」 |
| 4 | 标题避开「入侵 / 破解 / 劫持 / 拖库」等词，改用「分析 / 复现 / 调试」 |
| 5 | CTF writeup 可以保留（属常规内容），但不放完整、可直接复用的 RCE exploit |

**兜底机制**：UU 的合规否决权（见 2.2）。发现风险内容时，UU 可要求修改或下架。

**备案名与站点展示名解耦**

| 项 | 值 | 说明 |
|---|---|---|
| 备案网站名称 | **丞翰的技术笔记** | 备案系统的法定名称，受管局命名规则约束（≥ 3 个汉字、禁纯英文与特殊符号、禁企业类词汇） |
| 站点展示名 | **UU&Mixt** | 页面、Logo、页脚等处使用 |

`UU&Mixt` 含 `&` 且为纯英文，**不符合备案网站名称规则**，两者必须分开。两者会同时出现在页脚（备案号与站点名并列），属正常状态。

**备案号展示（强制）**：备案通过后，页脚必须展示备案号并链接至工信部备案管理系统查询页。

### 3.8 写作台（网页管理入口）

**目的**：让**两位作者都能在网页上完成发文与分类维护**（产品目标 G6）。Mixt 全程不接触代码与命令行；UU 保留本地写作路径，写作台作为可选的第二通道。

**形态已按 Demo 定稿**（`demo/admin.html` + `demo/admin-desk.html`，交互细节以 Demo 为准）：

| 项 | 规格 |
|---|---|
| 结构 | **登录门**（`/admin/`，每作者独立密码，登录页默认暗色门面）→ 验证后跳转到**独立工作台页**（`/admin/desk/`）；未登录访问工作台自动退回登录门 |
| 身份与权限 | 一个密码对应一位作者；进入后**身份锁定，只能管理自己那一面**的文章与分类（技术强制，优于原"靠约定"方案） |
| 文章面板 | 列表（标题/分类/日期/状态/操作合并为单列布局）、新建、编辑、删除、发布 ↔ 转草稿；**状态与操作合并为一列**（状态徽章居左、操作按钮居右） |
| **提交即发布** | 保存（非草稿）即进入发布队列，**无审核环节**（见 2.5）；草稿不进站点 |
| slug | **系统按标题自动生成**（作者不接触 URL 概念）：英文标题转 kebab-case，中文标题用"日期 + 序号"兜底（正式实现可接中文转拼音）；同面去重；**一经发布即冻结**（见 4.1 slug 规则） |
| 分类面板 | 每位作者**自维护自己面的分类**（新增/编辑/删除）；改名时同步该分类下文章的分类标签；点击分类项展开该分类文章的时间线；Mixt 面初始为空（3.5） |
| 媒体面板 | 文章配图的**引用生成器**：选择本地图片 → 缩略预览 → 生成正文引用代码（正式实现的仓库路径 `/images/<面>/文件名`）并复制。真正的文件上传由正式实现完成（图片随文章进仓库） |
| 设置 | 导出本面数据（JSON / 可扩展为带 front-matter 的 Markdown）、重置 Demo 数据 |
| 字段一致性 | 表单字段与 3.2 元数据一一对应（title/date/author/category/tags/description/featured/draft + 自动 slug），**不得出现 3.3 之外的字段** |
| 主题 | 写作台跟随明暗模式；登录页为暗色门面（页级默认主题，可手动切换） |

**后端选型（2026-09-14 UU 拍板：方案 B）**

| 项 | 规格 |
|---|---|
| 选型 | **GitHub Contents API 直提**（纯前端调用 REST API，**不新增任何服务器端常驻服务**，符合 6.1） |
| 登录方式 | **UU（仓库所有者）**：fine-grained PAT（Repository access 仅 `uu-mixt`，Permissions 仅 `Contents: Read and write`）。**Mixt（仓库协作者）**：只能用 **classic PAT**（勾 `repo`）——GitHub 官方限制「fine-grained PAT 不支持以仓库协作者身份写库」（Fine-grained PAT limitations）；代价是 classic token 覆盖其名下所有仓库，故要求设置过期时间。若日后希望 Mixt 也用最小权限凭据，可把仓库转入 Organization 并把 Mixt 加为成员 |
| 身份判定 | `GET /user` 的 login → 映射到面：`Karl-Heinrich-Marx-520` → uu，`Mixt170` → mixt；未授权账号拒绝进入 |
| 技术强制 | 写作台接口**不接受 face 参数**，所有写路径由会话推导并强制拼接 `src/content/<face>/` 与 `src/config/categories-<face>.json` → 越面写入在实现层不可能发生 |
| 凭据纪律 | PAT 只存作者自己的浏览器 localStorage；**不进仓库、不进构建产物**（6.6）；泄露后可即时吊销 |
| 落点 | 文章 `src/content/<face>/<slug>.md`；分类 `src/config/categories-<face>.json`；配图 `public/images/<face>/<文件名>`（正文引用 `/images/<face>/文件名`） |

**其余候选（保留备查，当前不采用）**

| 候选 | 说明 | 代价 |
|---|---|---|
| Decap CMS | Git-based，需一次性 OAuth 中转 | 外部依赖（原 3.8 方案，UI 可替换为 Demo 形态） |
| GitHub API 直提 | 工作台页面直接调 GitHub Contents API 提交文件 | 需 GitHub 登录 + 细粒度 token 授权 |
| 本地 git | UU 本地运行的小工具接收写作台提交 | 仅 UU 可用，Mixt 不可用（不满足 G6） |

**验收标准**：作者能在写作台完成「登录 → 写一篇带分类与标签的文章 → 保存 → 在自己面的首页/归档/分类页立刻看到 → 详情页可打开（Markdown 渲染 + 自动目录）」，全程不需要 UU 代劳；Demo 已用本地内容层完整验证此闭环。

### 4.2 双面翻转机制

| 项 | 规格 |
|---|---|
| 触发方式 | 右上角固定控件（两面位置一致）／键盘 `Alt + ←` `Alt + →`／触屏横向滑动（位移 > 60px 且速度 > 0.3px/ms，方向角 > 30° 才判定为横向）／面内导航链接 |
| 旋转轴 | Y 轴，`0° → 180°` |
| 时长 | 720ms |
| 缓动 | `cubic-bezier(0.22, 0.61, 0.36, 1)` |
| 透视 | `perspective: 2400px` |
| 景深 | 翻转中点 `scale(0.94)`，两端 `scale(1)` |
| 中途处理 | 两面均 `backface-visibility: hidden`；在 90° 时刻切换背景与主题变量 |
| **卡牌式形态（v2.0 随 Demo 定稿）** | 整页内容包于 `.page-card` 作为一张卡牌：翻出面绕 Y 轴 0 → ±89° 翻出，目标面从 ±89° 翻入归位；**缓慢高光带**自左向右扫过（跨页用 sessionStorage 衔接后半程），背景与内容在 90° 瞬间同时切换；转场粒子按下方转场条款执行 |
| 禁止（常驻） | 模糊、发光、渐变叠加、粒子等**常驻**特效——页面静止状态下不得存在 |
| 豁免（面视觉） | **面首页 Hero 整屏背景图**与**正文区同图常驻虚化背景**属视觉风格，不受上一条约束。代价与要求见下方「面视觉背景」 |
| 允许（转场瞬间） | 翻转/入场**转场过程中**允许：主题色粒子爆发、同心冲击波、卡片主题色微发光、短暂全屏闪光（峰值不透明度 ≤ 0.2，时长 ≤ 700ms）。转场结束即移除全部特效元素；`prefers-reduced-motion` 与无 JS 场景一律跳过 |

**面视觉背景（v1.4 新增）**

| 项 | 规格 |
|---|---|
| 构成 | 面首页首屏为**整屏清晰封面图**（`hero`），正文区以**同一张图常驻虚化**（`blur(26px)`）铺底 |
| 图源 | 每面一张，由该面作者指定；路径经 CSS 变量注入，换图不改代码 |
| 可读性 | 必须叠 veil（浅色 / 深色各一套），保证正文与背景的对比度 ≥ 4.5:1；卡片保留自身表面色 |
| 降级 | 图片加载失败时回退到纯色背景；`prefers-reduced-motion` 下静帧（blur 保留，无动画）；无 JS 时正常显示 |
| 性能 | 图片为构建期压缩的静态资源（单张 ≤ 400KB），`hero` 图需预加载，`background-attachment` 不使用 fixed 滚动重绘方案 |

**URL 同步**

| 场景 | 行为 |
|---|---|
| 站内点击翻转 | 播放动画 → `history.pushState` 改为对面路由 |
| 直接访问 `/uu/…` 或 `/mixt/…` | 直接呈现该面，`transition: none`，**不播放动画** |
| 浏览器后退 / 前进 | 监听 `popstate`，反向播放动画 |
| 刷新页面 | 落在当前 URL 对应的面 |

**降级**

| 场景 | 策略 |
|---|---|
| `prefers-reduced-motion: reduce` | 退化为 200ms 交叉淡入，无旋转无缩放 |
| 禁用 JavaScript | 两面内容均在 HTML 中；隐藏翻转控件；面间切换走整页跳转 |
| 键盘 | 翻转控件为原生 `<button>`，可聚焦、Enter 触发；切换后 `aria-live` 播报 |
| 屏幕阅读器 | 非活动面设置 `aria-hidden="true"` 与 `inert` |
| 文档标题 | 随面切换（如 `UU 的文章 · UU&Mixt`） |

**性能**：桌面 60fps、低端移动 ≥ 45fps；非活动面图片 `loading="lazy"`；翻转期间 CLS = 0。

### 4.3 入口页 `/`

**四状态流程**

| 状态 | 触发 | 规格 |
|---|---|---|
| S0 并列 | 页面加载 | 两卡并排（移动端纵向），各含头像、展示名、技术方向一句话、文章数、最近一篇标题。悬停抬升 4px、边框转强调色，160ms |
| S1 收拢重叠 | 点击其中一张卡 | 选中卡移至视口中心，`scale(1 → 1.06)`，置顶；另一卡移至同一中心，`scale(1 → 0.96)`、`rotate(-2.5deg)`、上偏 10px，置于下层。520ms，`cubic-bezier(0.33, 1, 0.68, 1)` |
| S2 整叠翻转 | 再次点击卡片堆 | 整叠绕 Y 轴翻 180°，`perspective: 1600px`，720ms，缓动同 4.2。正面为**选中作者**的面；卡背为站点标识 + "正在进入 UU 的一面"。90° 时切换卡片背景为主题色 |
| S3 放大入场 | 翻转完成 | 卡片 `scale(1.06 → 7)` + 淡出，420ms，与目标面交叉衔接。结束后 `history.pushState` 到 `/uu/`（或 `/mixt/`） |

**附加规格**
- 总时长约 1.7s
- S1 中未选中的卡片须从选中卡左上错出 10–14px，保留边缘可见
- S1 可逆：`Esc` 或点击卡片外空白 → 360ms 反向动画回到 S0
- S3 使用 `pushState`，使用户可后退回入口页

**降级与二次访问**

| 场景 | 策略 |
|---|---|
| `prefers-reduced-motion: reduce` | 跳过 S1/S2/S3，点击后 180ms 交叉淡入进入目标面 |
| 禁用 JavaScript | 卡片本身是 `<a href="/uu/">`，直接整页跳转 |
| 键盘 | Tab 聚焦 → Enter 进入 S1 → 再 Enter 触发 S2+S3；`Esc` 返回 S0 |
| 二次访问（`sessionStorage` 有标记） | 跳过入场动画，直接呈现 S0；上次访问过的卡片标注"上次访问" |
| 从 `/uu/` 返回入口页 | 直接呈现 S0，不重播动画 |

**入口页内容要素**
- 站点名与一句站点描述
- 两张作者卡片
- 翻牌操作的文字提示
- 站点级公共链接：RSS、全站搜索
- 底部一行小字：本站由 UU 与 Mixt 各自独立维护，两面内容互不干涉 · **关于本站**（链接到 `/about/`）

> 这一行小字是 `/about/` 页的**唯一入口** —— 不做导航栏入口，不占首屏视觉重量，但必须可点击、可键盘聚焦。

**性能**：只动画 `transform` 与 `opacity`；卡片数据由构建期注入，不发起网络请求；`will-change` 仅在动画期间添加；首屏 JS ≤ 15KB。

### 4.4 页面要素清单

**面首页 `/uu/` `/mixt/`**（形态已按 Demo 定稿）
- **首屏**：整屏高清封面（`hero`，每面一张，作者指定）+ 面名 + 方向标签 + 「下滑查看」引导；封面清晰不虚化（视觉规格见 4.2 的面视觉背景条款）
- **下滑后**：作者身份区（头像、展示名、简介、统计）→ 最新文章列表（标题 + 摘要 + 日期 + 标签）→ 归档入口、搜索入口
- 正文区域以**同图常驻虚化**铺底（4.2 面视觉背景条款：veil 保证对比度 ≥ 4.5:1）

- 条件：分类导航（分类配置非空时）
- 禁止：另一位作者的任何文章

**文章页**（形态已按 Demo 定稿）
- 必须：分类徽章、标题、作者与日期、正文、标签、上一篇/下一篇（限同面内）、分享按钮

- **目录**：由正文 h2/h3 自动生成，点击平滑滚动、高亮跟随当前章节
- 正文：代码块需语法高亮、行号、一键复制；图片可点击放大
- 修订：`updated` 晚于 `date` 时，文首显示"最后更新于 X"
- 合写：`authors` 为双值时并列显示两位作者
- 转载：文首固定位置展示来源与原文链接
- 跨面引用：需显式标注"（Mixt 的文章）"，避免读者误判所在面

**归档页**：按年份倒序分组，展示标题、日期、分类、标签；需提供分类与标签筛选视图

**分类页**：该分类下本面文章列表；分类配置为空时不生成

**标签页**：该标签下**跨两面**的文章列表；**每条结果必须标识所属作者**；页面需说明"标签为全站共享"

**作者页**：展示名、头像、技术方向简介、联系方式区（折叠）、该面文章统计

**关于本站页 `/about/`（共享）**
- **必须包含**：这个双面博客是什么、为什么用"两人各占一面"的组织方式、两位作者分别是谁（展示名 + 技术方向一句话 + 各自面的入口链接）、本站的技术形态一句话
- **角色区分**：作者页（`/uu/about/`、`/mixt/about/`）讲**个人**；关于本站页讲**站点本身**。两者不重复内容
- **入口**（2026-09-14 UU 拍板）：**入口页底部一行小字 + 两面页脚的站点级链接**（两处都放）
- **不做**：不做导航栏入口、不在两面的面内导航中出现

**搜索页**：见 5.1

**404 页**：识别来源面（URL 前缀），提供对应面返回入口 + 搜索框；不做彩蛋动画

| 内容上传入口 | 必须有网页入口（3.8），供 Mixt 独立发文；该入口为静态界面 + 外部 OAuth 中转 |
| 失败可见性 | 涉及作者日常操作的环节，失败必须可见（报错、非零退出），不得静默 |

### 6.2 技术方向

| 层面 | 采用 |
|---|---|
| 站点类型 | 静态站点生成（SSG） |
| 生成器 | Astro |
| 样式 | Tailwind + 两套 CSS 自定义属性（承载两面主题） |
| 翻转与入场动画 | 少量原生 JS / Web Component |
| 搜索 | 构建期静态索引（如 Pagefind） |
| 内容上传入口 | Decap CMS（构建期生成的静态管理界面，直接提交到 Git 仓库） |
| 服务器 | Nginx + Let's Encrypt 自动续期 |

**明确不采用**

| 不采用 | 说明 |
|---|---|
| Next.js SSR 常驻 | 内存超预算 |
| 数据库驱动的内容管理 | 与 Markdown 文件链路冲突，制造双真相源 |
| Docker 化 | 内存占用不划算 |
| 重量级动画库 | 只用 `transform` + History API |
| 服务器自建 Git 仓库 | 协作管理成本高 |
| 双远端推送部署 | 失败静默 |
| 任何自建评论后端 | 与零运维目标冲突 |
| 自建内容管理后台（数据库 + 常驻服务） | 改用 Decap CMS，无需自建服务端 |

### 6.3 部署

| 项 | 规格 |
|---|---|
| 仓库 | 单远端 GitHub **私有仓库**（命名 `origin`） |
| 部署方式 | 本地构建 → 一条命令手动上传 |
| 命令封装 | 仓库内 `deploy.sh`（不含凭据版本），日常只需记住一条命令 |
| **发布责任人** | **UU** —— 构建只能在本地做，因此所有发布动作由 UU 执行 |
| 回滚 | 不做自动回滚。恢复 = 重新构建并部署上一次可用提交（约 30 秒） |
| 备案归属 | **湖南省通信管理局**（按主体证件所在省） |
| 备案期间 | **暂停域名解析**，站点不得通过域名访问（首次备案期间开通访问会被阻断） |
| 上线顺序 | 备案通过 → 添加 A 记录 → 配置 Nginx → 443 + Let's Encrypt |
| 备案号 | 上线后页脚展示备案号并链接至工信部备案管理系统查询页（见 3.7） |

**部署脚本强制要求**

| 要求 |
|---|
| 明确打印同步的文件数量与目标位置 |
| 失败必须非零退出并打印原因 |
| 删除服务器上已不存在的旧文件（避免僵尸页面） |
| 凭据不得写入脚本 |

**开发期访问（备案期间）**
- 使用 `http://<公网IP>:8080` 一类非标准端口
- 仅供两位作者内部预览，不对外宣传、不提交搜索引擎
- **不加域名解析** —— 备案通过前加解析零收益且会被识别阻断
- 正式上线仅需添加解析、将 Nginx 监听端口改为 443 并挂证书

### 6.4 资源预算

| 资源 | 预算 |
|---|---|
| 服务器常驻内存（首期） | < 50MB（仅 Nginx） |
| 服务器常驻内存（**为未来 AI 助手预留**） | 约 200MB |
| 静态产物体积 | < 50MB |
| 首屏加载体积 | < 300KB（未压缩，不含图片） |
| 首屏 JS | < 30KB（未压缩），其中入口页 ≤ 15KB |
| 构建时间 | < 30s（文章数 200 篇以内） |

### 6.5 版本管理

| 项 | 规格 |
|---|---|
| 仓库可见性 | 私有 |
| 初始化 | `git init` + `AGENTS.md`（**M0，当前延后**） |
| 提交粒度 | 一文一提交 |
| 提交信息 | Conventional Commits（`feat` / `fix` / `docs` / `style`） |
| 图片资源 | 与文章同仓库管理，需压缩 |

### 6.6 信息安全纪律

| 风险 | 纪律 |
|---|---|
| 站点内容泄露 | 文章正文会公开，不写服务器真实 IP、内网拓扑、课题组内部资料、他人隐私 |
| 凭据泄露 | 服务器 IP、SSH 私钥、部署凭据**绝不入库**，放本地环境变量或 `~/.ssh/config` |
| 构建产物泄露 | 私有仓库 ≠ 私有网站。任何会进入前端产物的值都必须假定为公开 |
| 文档泄露 | 文档中不记录具体联系方式与服务器地址 |

仓库 `.gitignore` 需预先包含 `.env*`、`*.key`、`*.pem`、`deploy.local.sh`。

## 7. 非功能需求

### 7.1 SEO

| 项 | 要求 |

| 指标 | 目标 |
|---|---|
| LCP | < 2.5s（4G 网络） |
| CLS | < 0.1 |
| 首屏 JS | < 30KB（未压缩） |

| 非活动面 | `aria-hidden` + `inert` |
| 图片 | 内容图必须有 `alt`，装饰图用空 `alt` |

### 7.4 兼容性

| 浏览器 | 支持级别 |
|---|---|
