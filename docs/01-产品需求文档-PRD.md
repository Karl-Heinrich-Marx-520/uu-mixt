## 1. 定位与目标

### 1.1 一句话定位

**UU&Mixt** 是一个由两位技术作者各自独立经营的、可整站翻转的对称式技术博客。两人共享域名与视觉外壳，内容、导航、主题色与分类体系完全隔离。

### 1.2 站点信息

| 项 | 值 |
|---|---|
| 站点名称 | UU&Mixt |
| 域名 | **uuandmixt.com** |
| 备案状态 | 已有域名，**未备案** |
| 服务器 | 阿里云 ECS，2 vCPU / 2GB |
| 内容范围 | 技术笔记、源码阅读、项目复盘、论文复现、二进制安全与 PWN |
| 内容调性 | 偏硬、有工程细节、可复现；不写水文，不搬运热点 |
| 开发期访问 | 公网 IP + 非标准端口（如 `http://<IP>:8080`） |

### 1.3 目标用户

| 优先级 | 角色 | 核心诉求 |
|---|---|---|
| 主要 | 同行 / 同学 | 快速找到具体问题的解法，能看到可复现的细节 |
| 主要 | 面试官 / HR | 3 分钟内判断作者的技术深度与表达能力 |
| 次要 | 两位作者本人 | 检索自己过去写过的结论，充当个人知识库 |
| 非目标 | 泛技术资讯读者 | 不做热点内容，不为流量妥协 |

### 1.4 产品目标

| 编号 | 目标 | 验收标准 |
|---|---|---|
| G1 | 访客 3 秒内理解"这是两个人的博客、可以翻面" | 入口页两张作者卡片可见，不依赖解释性文字 |
| G2 | 每篇文章可独立分享，链接落到正确的一面 | 直接访问分享链接，落点正确且不播放翻转动画 |
| G3 | 两位作者发文互不干扰 | 一次发文只需改动自己面目录下的文件 |
| G4 | 部署一次不超过 3 条命令 | 构建 → 上传 → 生效，步骤写入 README |
| G5 | 单次搜索能找到两面的文章 | 结果中同时出现两位作者的文章，并标识归属 |

### 1.5 非目标

- 用户注册 / 登录体系
- 付费订阅、会员内容、广告位
- 移动端 App / 小程序 / 公众号同步
- 多语言 i18n
- 独立的"关于本站"页
- 评论区（首期）
- 在线写作后台（首期）

## 2. 协作与权限

### 2.1 协作模型：分栏自治

| 层面 | 归属 |
|---|---|
| 文章内容、归档 | 各自（由 `author` 字段决定） |
| 导航结构、主题色、分类体系、作者页 | 各自 |
| 域名、视觉外壳、翻转组件、入口页、404 页 | 共享 |
| 标签池、全站搜索、RSS | 共享（单实例） |

**硬性验收点**：任一面不得出现另一面的文章。

### 2.2 权限矩阵

| 操作 | UU | Mixt |
|---|---|---|
| 撰写 / 修改 / 删除自己的文章 | ✅ | ✅ |
| 发布自己的文章 | ✅ | ✅ |
| 修改对方的文章 | ❌ | ❌ |
| 修改对方的导航、主题色、分类配置 | ❌ | ❌ |
| 修改共享外壳（翻转 / 入口页 / 视觉框架） | 需双方同意 | 需双方同意 |
| 站点级设置（域名、部署脚本、搜索配置） | 需双方同意 | 需双方同意 |

### 2.3 技术维护者

**UU** 担任技术维护者。

| 项 | 规定 |
|---|---|
| 职责 | 部署脚本、服务器与 Nginx 配置、DNS 与 HTTPS 证书、站点故障、依赖升级、站点级备份 |
| 权限边界 | **不附带任何内容权限** —— 无权修改对方文章、导航、主题色、分类配置 |
| 紧急通道 | 站点不可访问、证书过期、被攻击时可直接操作，事后同步 |
| 交接 | 更换维护者时需完成部署文档、服务器凭据、域名管理权的交接 |

### 2.4 署名规则

| 场景 | 署名形式 | 规则 |
|---|---|---|
| 单人文章（默认） | 作者名 + 头像 | 由 `author` 决定归属面，只出现在该作者面 |
| 合写文章 | 双署名，主笔在前 | 使用 `authors: [uu, mixt]`；`author` 填主笔以决定归属面；需另一方在 PR 中确认后合入 |
| 转载他人内容 | 文首标注来源 | **允许转载**，但必须在文首标注来源与原文链接 |

**约束**
1. 文章归属以 `author` 为准，不因参与讨论而获得署名
2. 合写文章任一方有权要求移除自己的署名，此时降级为单人文章
3. 删除署名需在 PR 中留痕，不做静默修改

### 2.5 审核约定

**不实现审核状态机。** 审核能力由 Git 平台提供。

| 文章类型 | 流程 | 是否阻塞发布 |
|---|---|---|
| 单人文章 | 作者本地完成 → 构建 → 上传 | 不阻塞 |
| 合写文章 | 主笔开 PR → 另一方确认 → 合入 → 构建上传 | 阻塞 |
| 共享外壳改动 | 提 PR → 双方确认 | 阻塞 |
| 紧急故障修复 | 技术维护者直接操作 → 事后补 PR | 不阻塞 |

**注意**：GitHub 免费计划不包含分支保护与 Required reviewers，因此"未确认不发布"是**流程约定，不是技术强制**。它的价值在于留痕。

### 2.6 作者身份

| 项 | UU | Mixt |
|---|---|---|
| 展示名 | UU | Mixt |
| 技术方向 | C++ 后端 / 网络编程 / 科研复现 | PWN 二进制安全 |
| 简介 | 写 C++ 后端与网络编程，做过异步服务器与 Qt 客户端，也在复现 AI 集群的集合通信拥塞控制。落笔偏好可复现的细节与可验证的结论。 | 主攻 PWN 二进制安全。写漏洞分析、利用技巧与 CTF writeup。 |
| 头像 | `assets/avatars/uu.svg`（几何字母占位） | `assets/avatars/mixt.svg`（几何字母占位） |
| 联系方式 | 折叠的"联系方式"区，默认收起 | 同左 |

**约束**
- 两位作者的简介均为技术方向陈述，不写自我评价与形容词堆砌
- Mixt 的简介为占位草稿，**由其本人确认或改写**
- 联系方式由各作者在自己的作者页源文件中维护；本文档不记录具体值
- 联系方式默认折叠，点击后才由前端渲染文本，避免被批量爬取

### 2.7 分歧裁决

1. 提议方开 Issue，说明改动内容与影响
2. 48 小时无异议 → 执行
3. 有异议 → 双方协商；协商不成 → **维持现状**
4. 紧急故障由技术维护者直接执行，事后同步

## 3. 内容规范

### 3.1 生产与上线链路

```
① 本地写 Markdown（含元数据）
② 本地构建：schema 校验 + 分类校验 + 静态生成   ← 校验失败则中断
③ 本地预览：确认排版、翻转、链接
④ 一条命令上传到服务器
⑤ 线上生效（Nginx 提供静态文件，无重启、无进程）
```

约束：**构建一律在本地完成，服务器上不构建**。链路上不得出现常驻服务。

### 3.2 文章元数据

```yaml
---
title:       "文章标题"              # 必填, ≤ 60 字符
description: "一句话摘要"            # 必填, 60–120 字符
date:        2026-09-12              # 必填, YYYY-MM-DD
updated:     2026-10-01              # 可选, 有修订时填写
author:      uu                      # 必填, 枚举: uu | mixt
authors:     [uu, mixt]              # 可选, 仅合写文章
category:    网络编程                # 必填, 须在本面分类配置中已登记
tags:        [asio, 协程]            # 可选, string[], ≤ 5 个
cover:       /images/xxx.png         # 可选, 封面图
draft:       false                   # 可选, 默认 false
featured:    false                   # 可选, 置顶到面首页
---
```

### 3.3 校验规则（构建期强制执行）

| 字段 | 规则 | 失败后果 |
|---|---|---|
| `author` | 必须为 `uu` 或 `mixt` | 构建失败 |
| `category` | 必须在该面分类配置中已登记 | 构建失败，提示"未登记的分类" |
| `title` | 非空且 ≤ 60 字符 | 构建失败 |
| `description` | 60–120 字符 | 构建失败 |
| `tags` | 数量 ≤ 5，无空值 | 构建失败 |
| `date` | 合法日期且不晚于今天 | 构建失败 |
| 正文中的站内链接 | 目标必须存在 | 构建失败（死链检测） |

**报错要求**：必须包含文件路径、字段名与期望值。

### 3.4 文章状态

| 状态 | 声明方式 | 可见性 |
|---|---|---|
| 草稿 | `draft: true` | 不进构建产物；本地预览可见 |
| 已发布 | `draft: false` | 进入所属面的列表、归档、标签页、搜索结果与 sitemap |
| 下架 | 设回 `draft: true` | 线上消失，文件保留 |

状态由文件内容声明，**不存数据库**。仓库为私有，草稿可直接提交。

### 3.5 分类

| 项 | 规格 |
|---|---|
| 归属 | 每面独立维护 |
| 配置位置 | 每面一份分类配置文件 |
| 字段 | 名称、URL 短名、一句话描述、排序权重 |
| 新增分类 | 在配置文件中加一条记录，**无需改动代码** |
| 导航顺序 | 由配置文件中的先后顺序决定 |
| URL 短名 | 一经发布即冻结 |
| 空分类 | 该面不渲染分类导航、不生成分类页、文章页不显示分类标签，归档页隐藏分类筛选 |

**初始分类**

| 面 | 分类 |
|---|---|
| UU | `C++` / `网络编程` / `源码阅读` / `科研复现` / `工程实践` |
| Mixt | 空（由 Mixt 日后自行添加） |

### 3.6 标签

| 项 | 规格 |
|---|---|
| 归属 | **全站共享标签池** |
| 数量上限 | 每人 ≤ 30 个；每篇 ≤ 5 个 |
| 命名 | 专有名词按官方写法（`C++` / `Go`）；英文多词用连字符（`boost-asio`）；中文直接写 |
| 新增前 | 先在现有标签池中搜索是否已有同义标签 |
| 构建期提示 | 新标签与已有标签高度相似时给出警告（不阻断构建） |

## 4. 页面与交互

### 4.1 路由表

| 路由 | 归属 | 页面 |
|---|---|---|
| `/` | 共享 | 入口页 |
| `/uu/` | UU | 面首页 |
| `/uu/writing/` | UU | 归档（按年分组，支持分类/标签筛选） |
| `/uu/posts/<slug>/` | UU | 文章详情 |
| `/uu/categories/<cat>/` | UU | 分类列表 |
| `/uu/tags/<tag>/` | UU | 标签列表 |
| `/uu/about/` | UU | 作者页 |
| `/mixt/…` | Mixt | 同上镜像结构 |
| `/search/` | 共享 | 全站搜索 |
| `/rss.xml` | 共享 | RSS（另提供 UU / Mixt 单面 feed） |
| `/404` | 共享 | 错误页 |

**Slug 规则**：纯 `kebab-title`（如 `asio-coroutine-stack`），日期放在元数据中。slug 一经发布即冻结；必须修改时需登记重定向映射。

### 4.2 双面翻转机制

| 项 | 规格 |
|---|---|
| 触发方式 | 右上角固定控件（两面位置一致）／键盘 `Alt + ←` `Alt + →`／触屏横向滑动（位移 > 60px 且速度 > 0.3px/ms，方向角 > 30° 才判定为横向）／面内导航链接 |
| 旋转轴 | Y 轴，`0° → 180°` |
| 时长 | 720ms |
| 缓动 | `cubic-bezier(0.22, 0.61, 0.36, 1)` |
| 透视 | `perspective: 2400px` |
| 景深 | 翻转中点 `scale(0.94)`，两端 `scale(1)` |
| 中途处理 | 两面均 `backface-visibility: hidden`；在 90° 时刻切换背景与主题变量 |
| 动画属性 | **只允许 `transform` 与 `opacity`** |
| 禁止 | 模糊、发光、渐变叠加、粒子等特效 |

**URL 同步**

| 场景 | 行为 |
|---|---|
| 站内点击翻转 | 播放动画 → `history.pushState` 改为对面路由 |
| 直接访问 `/uu/…` 或 `/mixt/…` | 直接呈现该面，`transition: none`，**不播放动画** |
| 浏览器后退 / 前进 | 监听 `popstate`，反向播放动画 |
| 刷新页面 | 落在当前 URL 对应的面 |

**降级**

| 场景 | 策略 |
|---|---|
| `prefers-reduced-motion: reduce` | 退化为 200ms 交叉淡入，无旋转无缩放 |
| 禁用 JavaScript | 两面内容均在 HTML 中；隐藏翻转控件；面间切换走整页跳转 |
| 键盘 | 翻转控件为原生 `<button>`，可聚焦、Enter 触发；切换后 `aria-live` 播报 |
| 屏幕阅读器 | 非活动面设置 `aria-hidden="true"` 与 `inert` |
| 文档标题 | 随面切换（如 `UU 的文章 · UU&Mixt`） |

**性能**：桌面 60fps、低端移动 ≥ 45fps；非活动面图片 `loading="lazy"`；翻转期间 CLS = 0。

### 4.3 入口页 `/`

**四状态流程**

| 状态 | 触发 | 规格 |
|---|---|---|
| S0 并列 | 页面加载 | 两卡并排（移动端纵向），各含头像、展示名、技术方向一句话、文章数、最近一篇标题。悬停抬升 4px、边框转强调色，160ms |
| S1 收拢重叠 | 点击其中一张卡 | 选中卡移至视口中心，`scale(1 → 1.06)`，置顶；另一卡移至同一中心，`scale(1 → 0.96)`、`rotate(-2.5deg)`、上偏 10px，置于下层。520ms，`cubic-bezier(0.33, 1, 0.68, 1)` |
| S2 整叠翻转 | 再次点击卡片堆 | 整叠绕 Y 轴翻 180°，`perspective: 1600px`，720ms，缓动同 4.2。正面为**选中作者**的面；卡背为站点标识 + "正在进入 UU 的一面"。90° 时切换卡片背景为主题色 |
| S3 放大入场 | 翻转完成 | 卡片 `scale(1.06 → 7)` + 淡出，420ms，与目标面交叉衔接。结束后 `history.pushState` 到 `/uu/`（或 `/mixt/`） |

**附加规格**
- 总时长约 1.7s
- S1 中未选中的卡片须从选中卡左上错出 10–14px，保留边缘可见
- S1 可逆：`Esc` 或点击卡片外空白 → 360ms 反向动画回到 S0
- S3 使用 `pushState`，使用户可后退回入口页

**降级与二次访问**

| 场景 | 策略 |
|---|---|
| `prefers-reduced-motion: reduce` | 跳过 S1/S2/S3，点击后 180ms 交叉淡入进入目标面 |
| 禁用 JavaScript | 卡片本身是 `<a href="/uu/">`，直接整页跳转 |
| 键盘 | Tab 聚焦 → Enter 进入 S1 → 再 Enter 触发 S2+S3；`Esc` 返回 S0 |
| 二次访问（`sessionStorage` 有标记） | 跳过入场动画，直接呈现 S0；上次访问过的卡片标注"上次访问" |
| 从 `/uu/` 返回入口页 | 直接呈现 S0，不重播动画 |

**入口页内容要素**
- 站点名与一句站点描述
- 两张作者卡片
- 翻牌操作的文字提示
- 站点级公共链接：RSS、全站搜索
- 底部一行：本站由 UU 与 Mixt 各自独立维护，两面内容互不干涉

**性能**：只动画 `transform` 与 `opacity`；卡片数据由构建期注入，不发起网络请求；`will-change` 仅在动画期间添加；首屏 JS ≤ 15KB。

### 4.4 页面要素清单

**面首页 `/uu/` `/mixt/`**
- 必须：作者身份标识（头像、展示名、技术方向简介）、最新文章列表（标题 + 摘要 + 日期 + 标签）、归档入口、搜索入口
- 可选：置顶文章（`featured: true`）
- 条件：分类导航（分类配置非空时）
- 禁止：另一位作者的任何文章

**文章页**
- 必须：标题、作者与日期、正文、标签、上一篇/下一篇（限同面内）、分享按钮
- 正文：代码块需语法高亮、行号、一键复制；支持锚点目录；图片可点击放大
- 修订：`updated` 晚于 `date` 时，文首显示"最后更新于 X"
- 合写：`authors` 为双值时并列显示两位作者
- 转载：文首固定位置展示来源与原文链接
- 跨面引用：需显式标注"（Mixt 的文章）"，避免读者误判所在面

**归档页**：按年份倒序分组，展示标题、日期、分类、标签；需提供分类与标签筛选视图

**分类页**：该分类下本面文章列表；分类配置为空时不生成

**标签页**：该标签下**跨两面**的文章列表；**每条结果必须标识所属作者**；页面需说明"标签为全站共享"

**作者页**：展示名、头像、技术方向简介、联系方式区（折叠）、该面文章统计

**搜索页**：见 5.1

**404 页**：识别来源面（URL 前缀），提供对应面返回入口 + 搜索框；不做彩蛋动画

## 5. 搜索、分享与订阅

### 5.1 全站全文搜索

| 项 | 规格 |
|---|---|
| 方案 | 构建期生成静态全文索引，前端零后端查询 |
| 范围 | **两面全部文章**，覆盖标题、摘要、正文、标签、分类 |
| 结果标识 | **每条结果必须标识所属作者** |
| 能力 | 中文分词；标题权重高于正文；支持标签精确过滤 |
| 排序 | 相关性优先，其次按日期倒序 |
| 性能 | 索引不在首屏加载，进入搜索页时按需加载；输入响应 < 100ms |
| 边界 | 空输入显示"最近更新"；无结果时给出建议标签 |

## 6. 技术与部署

### 6.1 硬约束

| 约束 | 内容 |
|---|---|
| 服务器 | 阿里云 ECS，2 vCPU / 2GB，**构建不得在服务器上执行** |
| 作者技术背景 | 两位作者均不熟悉 web 前端，方案必须零维护、易排错 |
| 备案 | 域名未备案，**未备案时 80/443 端口被封禁（与是否绑定域名无关）** |
| 上线前提 | 备案通过 |
| 首期形态 | 无后台、无数据库、无 Node 常驻进程 |
| 失败可见性 | 涉及两位作者日常操作的环节，失败必须可见（报错、非零退出），不得静默 |

### 6.2 技术方向

| 层面 | 采用 |
|---|---|
| 站点类型 | 静态站点生成（SSG） |
| 生成器 | Astro |
| 样式 | Tailwind + 两套 CSS 自定义属性（承载两面主题） |
| 翻转与入场动画 | 少量原生 JS / Web Component |
| 搜索 | 构建期静态索引（如 Pagefind） |
| 服务器 | Nginx + Let's Encrypt 自动续期 |

**明确不采用**

| 不采用 | 说明 |
|---|---|
| Next.js SSR 常驻 | 内存超预算 |
| 数据库驱动的内容管理 | 与本地 Markdown 链路冲突 |
| Docker 化 | 内存占用不划算 |
| 重量级动画库 | 只用 `transform` + History API |
| 服务器自建 Git 仓库 | 协作管理成本高 |
| 双远端推送部署 | 失败静默 |
| 任何自建评论后端 | 与零运维目标冲突 |

### 6.3 部署

| 项 | 规格 |
|---|---|
| 仓库 | 单远端 GitHub **私有仓库**（命名 `origin`） |
| 部署方式 | 本地构建 → 一条命令手动上传 |
| 命令封装 | 仓库内 `deploy.sh`（不含凭据版本），日常只需记住一条命令 |
| 回滚 | 不做自动回滚。恢复 = 重新构建并部署上一次可用提交（约 30 秒） |
| 上线 | 备案通过后绑定域名 + 443 + Let's Encrypt |

**部署脚本强制要求**

| 要求 |
|---|
| 明确打印同步的文件数量与目标位置 |
| 失败必须非零退出并打印原因 |
| 删除服务器上已不存在的旧文件（避免僵尸页面） |
| 凭据不得写入脚本 |

**开发期访问**
- 使用 `http://<公网IP>:8080` 一类非标准端口
- 仅供两人内部预览，不对外宣传、不提交搜索引擎
- 正式上线仅需将 Nginx 监听端口改为 443 并挂证书

### 6.4 资源预算

| 资源 | 预算 |
|---|---|
| 服务器常驻内存（首期） | < 50MB（仅 Nginx） |
| 服务器常驻内存（**为未来 AI 助手预留**） | 约 200MB |
| 静态产物体积 | < 50MB |
| 首屏加载体积 | < 300KB（未压缩，不含图片） |
| 首屏 JS | < 30KB（未压缩），其中入口页 ≤ 15KB |
| 构建时间 | < 30s（文章数 200 篇以内） |

### 6.5 版本管理

| 项 | 规格 |
|---|---|
| 仓库可见性 | 私有 |
| 初始化 | `git init` + `AGENTS.md`（**M0，当前延后**） |
| 提交粒度 | 一文一提交 |
| 提交信息 | Conventional Commits（`feat` / `fix` / `docs` / `style`） |
| 图片资源 | 与文章同仓库管理，需压缩 |

### 6.6 信息安全纪律

| 风险 | 纪律 |
|---|---|
| 站点内容泄露 | 文章正文会公开，不写服务器真实 IP、内网拓扑、课题组内部资料、他人隐私 |
| 凭据泄露 | 服务器 IP、SSH 私钥、部署凭据**绝不入库**，放本地环境变量或 `~/.ssh/config` |
| 构建产物泄露 | 私有仓库 ≠ 私有网站。任何会进入前端产物的值都必须假定为公开 |
| 文档泄露 | 文档中不记录具体联系方式与服务器地址 |

仓库 `.gitignore` 需预先包含 `.env*`、`*.key`、`*.pem`、`deploy.local.sh`。

## 7. 非功能需求

### 7.1 SEO

| 项 | 要求 |
|---|---|
| 每页独立 title / description | 来自元数据，不得用站点默认值兜底 |
| 结构化数据 | 文章页输出 `Article` 类型 JSON-LD，含作者、日期、标题 |
| sitemap | 构建期生成，两面文章均收录并标注最后修改时间 |
| 语义化 URL | 见 4.1，禁止 ID 数字或查询参数型地址 |
| 翻转与收录 | 两面内容均为真实 HTML 且各有路由，可被独立收录 |
| 站内链接 | 使用相对路径，构建期校验死链 |

### 7.2 性能

| 指标 | 目标 |
|---|---|
| LCP | < 2.5s（4G 网络） |
| CLS | < 0.1 |
| 首屏 JS | < 30KB（未压缩） |
| 图片 | 统一转现代格式 + 按展示尺寸生成多档 |
| 动画 | 只动画 `transform` 与 `opacity` |

### 7.3 可访问性

| 项 | 要求 |
|---|---|
| 语义化标签 | 使用 `nav` / `main` / `article` / `aside` / `footer` |
| 键盘可达 | 所有交互元素可 Tab 聚焦、Enter/Space 触发，有可见焦点环 |
| 对比度 | 两套主题均满足 WCAG AA（正文 ≥ 4.5:1） |
| 减少动效 | 严格响应 `prefers-reduced-motion` |
| 非活动面 | `aria-hidden` + `inert` |
| 图片 | 内容图必须有 `alt`，装饰图用空 `alt` |

### 7.4 兼容性

| 浏览器 | 支持级别 |
|---|---|
| Chrome / Edge 最近两个大版本 | 完整支持 |
| Safari（含 iOS） | 完整支持 |
| Firefox 最近两个大版本 | 完整支持 |
| 国产浏览器（QQ / 360 / 搜狗） | 基本可读（动画可降级） |
| IE | 不支持 |

### 7.5 可维护性

| 项 | 要求 |
|---|---|
| 新增文章无需改代码 | 只需新建 Markdown 文件；路由、列表、标签页、搜索索引、sitemap 自动更新 |
| 新增分类无需改代码 | 只需在分类配置中加一条记录 |
| 部署步骤文档化 | README 写明完整部署命令 |
| 错误可定位 | 构建报错必须包含文件路径与字段名 |
| 依赖克制 | 生产依赖不超过 10 个；新增依赖需说明用途 |
